7. ระบบตระกูล Store (StorePC / StoreSP / StoreRM / StoreWIP / StoreMAT)

===========================================================================
ที่มา: พัฒนาต่อยอดจาก StorePC เวอร์ชัน Windows Forms ในหัวข้อก่อนหน้า เดิมไม่มีระบบบริหารสต็อกที่สมบูรณ์ ใช้วิธีนับมือเขียนยอดบนบอร์ดตอนเช้าเพียงครั้งเดียว ทำให้ไม่มีใครทราบสต็อกจริงตลอดวัน

System Analysis & Design
- วิเคราะห์โครงสร้าง Full Barcode จาก ERP เพื่อรองรับ Traceability ระดับ Work Order
- ออกแบบ Data Flow (DFD) และโครงสร้างระบบรองรับ Real-time processing ผ่าน TCP/IP

Development (Full-Stack)
- พัฒนา Dynamic Barcode Parsing แยกข้อมูล LOT, Work Order, QTY จาก ERP
- ระบบ Real-time Stock Update จากเครื่อง Scanner, History Logging & Audit Trail
- ระบบกำหนดสิทธิ์การใช้งานรายบุคคล พร้อม Log กิจกรรมและชื่อเครื่อง Login
- Dynamic Import (Excel) สำหรับ Forecast และ Max-Min ที่ผู้ใช้กำหนดค่าการคำนวณเองได้ตามรอบลูกค้า
- สร้าง QR Code, หน้า Inventory Registration, กราฟวงกลม Order ลูกค้า, กราฟ Forecast Delivery รายปี Reset อัตโนมัติ
- ระบบ Data Security (Soft Delete / Show-Hide Logic)
- ขยายเป็นระบบตระกูลเดียวกัน: StoreRM (Raw Material), StoreWIP (Work In Process), StoreMAT (Material) — พัฒนาต่อจาก StoreSP ใช้เวลาเพียงระบบละ 1 วัน (เปลี่ยนแค่ Database และ Detail หน้าจอ)
- StorePC เวอร์ชันใหม่: อัปเกรดจากตัวเก่า (Windows Forms ธรรมดา ไม่มี View/Stored Procedure/Trigger) เป็น WPF MVVM เต็มรูปแบบ มี View ครบเหมือนระบบอื่นในตระกูล Deploy ด้วย ClickOnce สร้างขึ้นเองคนเดียวทั้งหมด

Performance
- โหลดข้อมูลแบบแบ่งหน้า (เริ่ม 10 รายการ +20 ต่อการเลื่อน สูงสุด 60), สร้าง Index ค้นหา, ใช้ Async/Await และ Stored Procedure คำนวณเบื้องหลัง ป้องกันระบบค้าง

Testing & QA
- ใช้ RPA จำลองข้อมูลจำนวนมาก (Stress Test) และทำ UAT ร่วมกับหน้างานจริง

Deployment & Training
- Deploy ด้วย ClickOnce ให้อัพเดทได้โดยไม่ต้องปิดโปรแกรม, จัดทำ User Manual/เอกสารเทคนิค, Training ผู้ใช้งานทุกระดับ

ระยะเวลาพัฒนา StoreSP: 3 เดือน 11 วัน

Result / Impact: เพิ่ม Traceability ระดับ Work Order, ลดข้อจำกัดของ ERP เดิม, เพิ่มความเร็วเข้าถึงข้อมูล, เชื่อมต่อข้อมูลแบบ Seamless Integration

8. EDP Planing — ระบบวางแผนการผลิตไลน์ EDP
   พัฒนาด้วยตนเองคนเดียวทั้งหมด — Platform: WPF (MVVM) / SQL Server
=================================================================
พัฒนาระบบให้พนักงานวางแผนการผลิตได้จากออฟฟิศ โดยไม่ต้องเดินไปวางแผนที่บอร์ดหน้างาน แสดงผลที่หน้าจอหน้างานได้ทันที รองรับการปรับยอดแผนแบบ Real-time (เช่น ผลิตเพิ่ม +3.25 หรือผลิตไม่ทัน -3.25 ต่อการ์ด) มีหน้า Set Plan ที่ Export ข้อมูลพร้อมคำนวณเวลาให้ User นำไปใช้งานต่อได้ทันทีโดยไม่ต้องคีย์ซ้ำ

System Analysis & Design
- วิเคราะห์ปัญหาเดิม (ต้องเดินไปวางแผนที่บอร์ดหน้างาน, ปรับแผนกลางไลน์ผลิตไม่ทันสถานการณ์จริง) และรวบรวม Requirement จากพนักงานวางแผนการผลิต
- ออกแบบ Data Flow (DFD) ให้รองรับการวางแผนจากออฟฟิศและซิงค์ผลไปแสดงที่จอหน้างานได้ทันที
- ออกแบบโครงสร้างข้อมูล Plan/Card รองรับการปรับยอดแบบ Real-time (เพิ่ม/ลดจำนวนต่อการ์ด)

Development (Full-Stack)
- พัฒนาหน้า Set Plan สำหรับพนักงานวางแผนกำหนดแผนการผลิตล่วงหน้า พร้อมฟังก์ชัน Export ข้อมูลและคำนวณเวลาให้อัตโนมัติ ไม่ต้องคีย์ซ้ำ
- พัฒนาระบบซิงค์ข้อมูลแบบ Real-time ระหว่างหน้า Set Plan และจอแสดงผลหน้างาน ให้ปรับยอด (เช่น +3.25 / -3.25 ต่อการ์ด) เห็นผลทันที
- ออกแบบ UI ให้อ่านง่ายบนจอหน้างาน เน้นตัวเลขและสถานะแผนที่ชัดเจน ลดโอกาสอ่านผิด

Performance
- ใช้ Async/Await ในการดึงและอัพเดทข้อมูลแผน ป้องกันหน้าจอค้างระหว่างมีการปรับยอดพร้อมกันหลายจุด
- ใช้ Stored Procedure คำนวณเวลาและยอดผลิตเบื้องหลัง ลดภาระการประมวลผลฝั่ง Client

Testing & QA
- ทดสอบการปรับยอดแผนแบบ Real-time เทียบกับสถานการณ์ผลิตจริงหน้าไลน์
- ทำ UAT ร่วมกับพนักงานวางแผนการผลิตและหน้างานจริง ตรวจสอบความถูกต้องของการ Export และคำนวณเวลา

Deployment & Training
- Deploy ด้วย ClickOnce ให้อัพเดทเวอร์ชันได้โดยไม่ต้องปิดโปรแกรม
- จัดทำ User Manual และ Training พนักงานวางแผนการผลิตและหน้างานให้ใช้งานระบบได้ครบทุกฟังก์ชัน

9. SmartOps System — ระบบ Import PDF กรองข้อมูลอัตโนมัติ
   พัฒนาด้วยตนเองคนเดียวทั้งหมด — Platform: WPF (MVVM)
====================================================
พัฒนาเป็นเครื่องมือ IT Support สำหรับ Import ไฟล์ PDF และ Export ข้อมูลออกเป็น Excel Template ที่ออกแบบไว้ ใช้สร้างเอกสาร PR รับสินค้าเข้าคลังเหล็ก โดย User Export ข้อมูลแล้วส่งต่อให้ RPA กรอกเข้าระบบอัตโนมัติทันที ไม่ต้องกรอกข้อมูลเอง

System Analysis & Design
- วิเคราะห์รูปแบบเอกสาร PDF ที่ใช้งานจริงหลายแบบ (เช่น Commercial Invoice, Mill Test Certificate) แต่ละแบบมีตำแหน่งข้อมูลในกรอบสี่เหลี่ยมสีแดงไม่เหมือนกัน
- ออกแบบโครงสร้างโปรแกรมแบบ MVVM แยก Views/ViewModels/Services ชัดเจน โดยไม่มีฐานข้อมูล ทำหน้าที่กรองและแปลงข้อมูลอย่างเดียว
- ออกแบบ Excel Template สำหรับ Export ให้ตรงตามรูปแบบเอกสาร PR ที่ใช้งานจริง

Development
- พัฒนาหน้า Dropdown ให้ User เลือกประเภทเอกสารก่อน Import เนื่องจากแต่ละประเภทมีตำแหน่งกรอบข้อมูลไม่เหมือนกัน
- พัฒนาโมดูล Import PDF และกรองข้อมูลเฉพาะส่วนที่อยู่ในกรอบสี่เหลี่ยมสีแดงตามประเภทเอกสารที่เลือก
- พัฒนาฟังก์ชัน Export ข้อมูลที่กรองได้ไปใส่ Excel Template ที่ออกแบบไว้ พร้อมจัดตำแหน่งข้อมูลให้ตรงตามช่องที่กำหนด
- เชื่อมต่อ Output ของระบบให้ส่งต่อให้ RPA กรอกเข้าระบบ ERP อัตโนมัติทันที ไม่ต้องกรอกข้อมูลเอง

Testing & QA
- ทดสอบ Import เอกสารจริงหลากหลายประเภท ตรวจสอบความแม่นยำของตำแหน่งกรอบแดงที่กรองได้ในแต่ละประเภทเอกสาร
- ทำ UAT ร่วมกับ User ฝ่ายจัดซื้อ/คลังเหล็กที่ใช้งานจริง ตรวจสอบข้อมูลที่ Export ไป Excel Template ว่าตรงตามที่ RPA ใช้กรอกต่อได้

Deployment & Training
- Deploy ด้วย ClickOnce ให้อัพเดทเวอร์ชันได้โดยไม่ต้องปิดโปรแกรม
- จัดทำ User Manual และ Training ผู้ใช้งานฝ่ายที่เกี่ยวข้องให้เลือกประเภทเอกสารและ Export ข้อมูลได้ถูกต้อง

Result / Impact
- ลดเวลากรอกข้อมูลเอกสาร PR ด้วยมือ ลด Human Error จากการกรอกข้อมูลซ้ำ
- เชื่อมต่อการทำงานกับ RPA ได้แบบไร้รอยต่อ (Seamless)

10. WebOT / Web Stock เหล็ก
   พัฒนาด้วยตนเองคนเดียวทั้งหมด — Platform: Next.js / TypeScript / Tailwind CSS / ASP.NET Core / WebSocket / SQL Server
=========================================================================================================================
WebOT: พัฒนาเว็บดึงข้อมูลชั่วโมง OT ของพนักงานจาก ERP มาแสดง เพื่อให้ผู้บริหารและหัวหน้าฝ่ายดูภาพรวมชั่วโมง OT ของแต่ละหน่วยงานประกอบการตัดสินใจและควบคุม OT จากปัญหาดูยากบนมือถือ จึง Redesign ใหม่ทั้งหมดด้วย Next.js, TypeScript, React, Tailwind CSS, ASP.NET Core, WebSocket, SQL Server แสดงข้อมูลแบบปฏิทินแยกวันปกติ/วันหยุด อัพเดท Real-time ทุก 30 นาที

Web Stock เหล็ก: พัฒนาเพิ่มเติมจากปัญหาการทำงานซ้ำซ้อน เนื่องจากข้อมูล PO/PR อยู่ตรงกลางของระบบ ERP ไม่สามารถแยกระบบออกมาทำเองได้ทั้งหมด จึงออกแบบให้ดึงข้อมูลจาก ERP โดยตรงแทน พร้อมให้ User กำหนดค่า Max/Min ได้เอง รองรับการใช้งาน Responsive ทุกอุปกรณ์ทั้ง Mobile และ Desktop

Tech Stack ที่ใช้
- Frontend: Next.js, React, TypeScript, Tailwind CSS
- Backend: ASP.NET Core Web API
- Real-time: WebSocket
- Database: SQL Server
- Version Control: Git
- Process Manager / Deploy: PM2

System Analysis & Design
- วิเคราะห์ปัญหาเดิม (หน้าจอดูยากบนมือถือ, ข้อมูล OT กระจัดกระจาย, ข้อมูล PO/PR ซ้ำซ้อนกับ ERP) และรวบรวม Requirement จากผู้บริหารและหัวหน้าฝ่าย
- ออกแบบโครงสร้างระบบแบบ Frontend (Next.js) แยกจาก Backend (ASP.NET Core Web API) สื่อสารกันผ่าน REST API และ WebSocket
- ออกแบบ Database Schema และ Data Flow สำหรับดึงข้อมูลจาก ERP มาประมวลผล

Development (Full-Stack)
- ตั้งค่า Repository ด้วย Git แยก Branch ตามฟีเจอร์ (Feature Branch) เพื่อควบคุมเวอร์ชันโค้ด
- พัฒนา Backend ด้วย ASP.NET Core Web API เชื่อมต่อ SQL Server ดึงข้อมูลชั่วโมง OT และข้อมูล PO/PR จาก ERP
- พัฒนา WebSocket Server สำหรับส่งข้อมูล Real-time อัพเดททุก 30 นาที โดยไม่ต้อง Refresh หน้าเว็บ
- พัฒนา Frontend ด้วย Next.js + TypeScript + React ออกแบบหน้าปฏิทินแยกวันปกติ/วันหยุด และหน้า Web Stock เหล็กให้ User กำหนดค่า Max/Min ได้เอง
- จัดหน้าตาและ Layout ด้วย Tailwind CSS ให้ Responsive รองรับทั้ง Mobile และ Desktop

Testing & QA
- ทดสอบ API และ WebSocket Connection ด้วยข้อมูลจริงจาก ERP
- ทำ UAT ร่วมกับผู้บริหารและหัวหน้าฝ่ายผู้ใช้งานจริง ตรวจสอบความถูกต้องของข้อมูล OT และ PO/PR

Deployment (PM2)
- Build โปรเจกต์ Next.js เป็น Production Build (next build)
- ติดตั้งและตั้งค่า PM2 บน Server เพื่อรัน Next.js และ ASP.NET Core ให้ทำงานอยู่เบื้องหลังตลอดเวลา (Background Process)
- ตั้งค่า PM2 Start Script (ecosystem.config.js) กำหนดชื่อ Process, จำนวน Instance และ Environment Variables
- ใช้คำสั่ง pm2 start, pm2 save และ pm2 startup เพื่อให้ระบบรันอัตโนมัติทันทีเมื่อ Server รีสตาร์ท
- ตั้งค่า Reverse Proxy (เช่น Nginx) ชี้เข้าพอร์ตที่ PM2 รันอยู่ พร้อมเปิดใช้งาน HTTPS
- Monitor สถานะ Process และ Log ผ่าน PM2 (pm2 logs, pm2 monit) เพื่อตรวจสอบและแก้ไขปัญหาได้ทันทีหลัง Deploy จริง

พัฒนาระบบสำหรับบันทึกข้อมูลโปรเจกต์ทั้งหมดที่เคยทำ พร้อม Presentation Timeline แสดงพัฒนาการเป็นเฟส บันทึกผล Tester และสร้าง Flow Diagram อัตโนมัติจากข้อมูลที่กรอก มีหน้า Preview ให้หัวหน้าฝ่ายและผู้จัดการเข้ามาติดตามและตรวจสอบรายละเอียดของแต่ละระบบ

Tech Stack ที่ใช้
- Frontend: Next.js, React, TypeScript, Tailwind CSS
- Backend: ASP.NET Core Web API
- Real-time: WebSocket
- Database: SQL Server
- Version Control: Git
- Process Manager / Deploy: PM2

System Analysis & Design
- วิเคราะห์ปัญหาเดิม (ไม่มีที่รวมบันทึกข้อมูลโปรเจกต์ที่เคยทำ ทำให้ติดตามความคืบหน้าและผลทดสอบย้อนหลังยาก) และรวบรวม Requirement จากหัวหน้าฝ่ายและผู้จัดการ
- ออกแบบโครงสร้างระบบแบบ Frontend (Next.js) แยกจาก Backend (ASP.NET Core Web API) สื่อสารกันผ่าน REST API และ WebSocket
- ออกแบบโครงสร้างข้อมูลโปรเจกต์แบบแบ่งเฟส รองรับการบันทึก Presentation Timeline, ผล Tester และสร้าง Flow Diagram อัตโนมัติจากข้อมูลที่กรอก

Development (Full-Stack)
- ตั้งค่า Repository ด้วย Git แยก Branch ตามฟีเจอร์ (Feature Branch) เพื่อควบคุมเวอร์ชันโค้ด
- พัฒนา Backend ด้วย ASP.NET Core Web API เชื่อมต่อ SQL Server สำหรับบันทึกข้อมูลโปรเจกต์, เฟส และผล Tester
- พัฒนา WebSocket สำหรับอัพเดทหน้า Preview แบบ Real-time เมื่อมีการกรอกหรือแก้ไขข้อมูลโปรเจกต์
- พัฒนา Frontend ด้วย Next.js + TypeScript + React ทำหน้า Presentation Timeline, บันทึกผล Tester และหน้า Preview ให้หัวหน้าฝ่ายและผู้จัดการเข้าถึงได้
- พัฒนาฟังก์ชันสร้าง Flow Diagram อัตโนมัติจากข้อมูลที่กรอก ลดเวลาจัดทำเอกสารด้วยมือ
- จัดหน้าตาและ Layout ด้วย Tailwind CSS ให้ Responsive รองรับทั้ง Mobile และ Desktop

Testing & QA
- ทดสอบ API และ WebSocket Connection รวมถึงความถูกต้องของ Flow Diagram ที่สร้างอัตโนมัติเทียบกับข้อมูลที่กรอกจริง
- ทำ UAT ร่วมกับหัวหน้าฝ่ายและผู้จัดการผ่านหน้า Preview ตรวจสอบว่าติดตามรายละเอียดแต่ละระบบได้ครบถ้วน

Deployment (PM2)
- Build โปรเจกต์ Next.js เป็น Production Build (next build)
- ติดตั้งและตั้งค่า PM2 บน Server เพื่อรัน Next.js และ ASP.NET Core ให้ทำงานอยู่เบื้องหลังตลอดเวลา (Background Process)
- ตั้งค่า PM2 Start Script (ecosystem.config.js) กำหนดชื่อ Process, จำนวน Instance และ Environment Variables
- ใช้คำสั่ง pm2 start, pm2 save และ pm2 startup เพื่อให้ระบบรันอัตโนมัติทันทีเมื่อ Server รีสตาร์ท
- ตั้งค่า Reverse Proxy (เช่น Nginx) ชี้เข้าพอร์ตที่ PM2 รันอยู่ พร้อมเปิดใช้งาน HTTPS
- Monitor สถานะ Process และ Log ผ่าน PM2 (pm2 logs, pm2 monit) เพื่อตรวจสอบและแก้ไขปัญหาได้ทันทีหลัง Deploy จริง
